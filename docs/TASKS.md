# Нарезка задач (итерация 1 — MVP)

Архитектор: создаёт каркас, контракты, раздаёт задачи, принимает по критериям, возвращает на доработку.
Исполнители: 4 параллельных агента (Opus), у каждого свой контекст и своя папка `src/features/<feature>/`.

## Контракты между фичами (фиксированы, менять только через архитектора)

- Маршруты — см. комментарий в `src/app/router.tsx`. Дополнительно:
  - `GET /workouts/start/:programId/:dayId` — создаёт сессию из дня программы и редиректит на `/workouts/session/:id` (владелец: A).
    Если есть незавершённая сессия (`finishedAt` пустой) — редирект на неё вместо создания новой.
  - `/cardio/new?type=run` — форма новой активности с предвыбранным типом (владелец: B).
  - `/nutrition?date=YYYY-MM-DD` — дневник питания за день (владелец: C).
  - `/sleep/new` — форма записи сна (владелец: B).
- «Активная тренировка» = запись в `sessions` без `finishedAt`. Одновременно может быть не более одной.
- Объём подхода = `weightKg × reps` для `done && !warmup`. 1RM (Epley) = `w × (1 + reps/30)`.
- Нормы питания считаются из `profile` (+ последняя запись `weights` вместо `profile.weightKg`, если есть)
  функцией `computeTargets(profile, weightKg)` из `src/features/nutrition/calc.ts`. Агент D (дашборд) может
  импортировать эту функцию — это единственный разрешённый импорт между фичами.

## Агент A — Зал: программы, сессия, библиотека упражнений (G1, G2)

Папка: `src/features/workouts/`

### A1. Список программ и день по расписанию
- `/workouts`: карточка «Сегодня по плану» (день программы по `weekday` = `weekdayIndex()`), кнопка «Начать тренировку»
  (или «Продолжить», если есть активная сессия). Ниже — список программ (`db.programs`), ссылка на историю и библиотеку.
- `/workouts/programs/:id`: дни программы, для каждого — упражнения с `sets × reps`, интенсивность, отдых;
  тап по упражнению → `/workouts/exercises/:exerciseId`. Кнопка «Начать этот день».
- Приёмка: при пустой БД после сидирования страница показывает David Laid DUP и день недели; `rest`-день показывает заметку и не даёт «Начать».

### A2. Сессия тренировки (логирование подходов)
- `/workouts/start/:programId/:dayId` — создаёт `WorkoutSession` (копирует упражнения дня: `targetSets`, `targetReps`, `restSec`,
  создаёт `targetSets` пустых `SetLog`) и редиректит на `/workouts/session/:id`.
- `/workouts/session/:id`: список упражнений; у каждого — `<ExerciseMedia>` (сворачиваемый), краткая инструкция (первые 2 шага,
  «показать всё»), план, таблица подходов: № · вес (Stepper, шаг 2,5) · повторы (Stepper) · RPE (опц.) · чекбокс «готово».
- Подсказка «Прошлый раз: 80 кг × 5, 5, 5» из последней завершённой сессии с тем же `exerciseId`. Кнопка «Повторить прошлый вес».
- При отметке подхода «готово» запускается таймер отдыха (`restSec`) с большими цифрами и кнопками «+30 с», «Пропустить»; по нулю — вибрация (`navigator.vibrate`, если есть) и визуальный сигнал.
- Добавить подход / удалить подход / добавить упражнение из библиотеки (поиск в `Sheet`) / удалить упражнение.
- «Завершить»: ставит `finishedAt`, показывает итог (длительность, объём, число подходов, новые рекорды) и ссылку на историю.
  Незавершённая сессия сохраняется при перезагрузке страницы (всё пишется в БД сразу).
- Приёмка: тест — старт дня создаёт сессию с правильным числом упражнений/подходов; тест — расчёт объёма и 1RM (`calc.ts`); повторный заход на `/workouts/start/...` при активной сессии не создаёт вторую.

### A3. История
- `/workouts/history`: список сессий по дате (название, длительность, объём, число подходов); тап → `/workouts/session/:id` в режиме просмотра (редактирование разрешено).
- Удаление сессии с подтверждением.

### A4. Библиотека упражнений
- `/workouts/exercises`: поиск по названию (без учёта регистра), фильтры-чипы: мышца (`MUSCLE_RU`), оборудование (`EQUIPMENT_RU`), категория (`CATEGORY_RU`). Виртуализация не нужна, но рендерить не более 60 карточек с кнопкой «Показать ещё».
- `/workouts/exercises/:id`: `<ExerciseMedia>`, инструкция по шагам, мышцы (основные/вспомогательные), уровень, оборудование;
  история моих подходов по этому упражнению (последние 10 сессий) и рекорд (max вес, расчётный 1RM).
- Приёмка: тест рендера списка с `__setExercisesForTests()` и фильтрацией.

## Агент B — Кардио, активности, растяжка, сон (G3, G5)

Папка: `src/features/cardio/` и `src/features/sleep/`

### B1. Активности
- `/cardio`: сводка текущей недели (минуты, км, число сессий по типам), быстрые кнопки «+ Бег», «+ Вело», «+ Бассейн», «+ Скакалка», «+ Ходьба», «+ Растяжка»; список последних активностей с удалением.
- `/cardio/new?type=…`: форма: тип, дата (по умолчанию сегодня), длительность (мин), дистанция (км) для run/bike/swim/walk, количество прыжков для rope, средний пульс, ккал (авто-оценка по MET × вес × часы, редактируемая), заметка.
  MET: run 9.8, bike 7.5, swim 8.0, rope 11.0, walk 3.5, stretch 2.5, hiit 10.0, other 5.0. Вес — из последней записи `weights`, иначе из `profile`.
- Для бега/плавания показывать темп (мин/км или мин/100 м) при наличии дистанции.
- Приёмка: тест `calc.ts` — ккал по MET и темп; тест рендера формы и сохранения в БД.

### B2. Растяжка
- `/cardio/stretch`: 3 встроенных комплекса (определить в `stretchRoutines.ts`, упражнения — только `category === 'stretching'` из библиотеки, проверить id тестом):
  «После ног» (квадрицепс, бицепс бедра, икры, ягодицы, поясница), «После верха» (грудь, плечи, широчайшие, трицепс, шея), «Утренняя мобилити» (всё тело, 8–10 мин).
- Режим выполнения: текущее упражнение с `<ExerciseMedia>`, таймер (по умолчанию 30 с на сторону), «Далее», прогресс «3/9». По завершении — сохраняет `Activity` типа `stretch` с `exerciseIds` и длительностью.
- Приёмка: тест — все `exerciseId` комплексов существуют в библиотеке и имеют категорию stretching.

### B3. Сон
- `/sleep`: сводка (прошлая ночь, среднее за 7 дней, цель из `profile.sleepTargetMin`), график за 14 дней (Recharts, столбики часов с линией цели), список записей с удалением.
- `/sleep/new`: отбой (datetime), подъём (datetime), качество 1–5 (кнопки), заметка. `durationMin` вычисляется; `date` = день подъёма. Валидация: подъём после отбоя, длительность < 16 ч.
- Приёмка: тест `calc.ts` — длительность через полуночь, среднее за 7 дней; тест рендера формы.

## Агент C — Питание (G4)

Папка: `src/features/nutrition/`

### C1. Расчёт нормы — `calc.ts` + `/nutrition/plan`
- `computeTargets(profile, weightKg)`: BMR по Mifflin–St Jeor (мужчины: 10w + 6.25h − 5a + 5; женщины −161), возраст = текущий год − `birthYear`;
  TDEE = BMR × коэффициент активности (1.2 / 1.375 / 1.55 / 1.725 / 1.9); цель: cut −18 %, maintain 0, lean_bulk +10 %;
  `kcalTargetOverride` переопределяет ккал. Белок = `proteinPerKg` (по умолч. 2.0) × вес; жиры 0.9 г/кг; углеводы — остаток / 4. Возвращает `{ bmr, tdee, kcal, proteinG, fatG, carbsG }` (целые).
- Страница показывает эти числа с объяснением формулы, позволяет задать/сбросить `kcalTargetOverride` (пишет в `db.profile`). Ссылка на `/settings` для изменения роста/веса/цели.
- Приёмка: тест — для 183 см / 88 кг / 26 лет / active / cut: BMR 1 892 ±2, TDEE 3 264 ±5, kcal ≈ 2 676.

### C2. Дневник дня — `/nutrition`
- Переключатель даты (← сегодня →), 4 прогресс-бара: ккал, белок, жиры, углеводы (съедено / цель), блоки по приёмам пищи (завтрак, обед, ужин, перекус) с записями и «+ Добавить».
- Добавление: `Sheet` с поиском по `db.foods` + встроенный стартовый список ~40 базовых продуктов (seed в `foods` при первом открытии, `isBuiltIn: true`: куриная грудка, рис, овсянка, яйца, творог, гречка, банан, яблоко, лосось, говядина, картофель, молоко, кефир, хлеб, макароны, оливковое масло, орехи, протеин сывороточный и др. — реальные значения на 100 г). Ввод граммов → пересчёт КБЖУ; «быстрый ввод» вручную (название + ккал/Б/Ж/У). Редактирование и удаление записи.
- Вода: кнопка «+250 мл», «+500 мл», цель из `profile.waterTargetMl`, прогресс-бар, список с удалением.
- Приёмка: тест — пересчёт КБЖУ на граммы; тест рендера дневника: добавил запись → суммы обновились.

### C3. Мои продукты — `/nutrition/foods`
- Список продуктов с поиском, добавление/редактирование/удаление пользовательских; встроенные нельзя удалить, можно скопировать.

### D3. Настройки — `/settings`

- Кнопка «Сбросить данные» с подтверждением (очищает все таблицы и повторно вызывает `ensureSeeded`).

## Агент E — Календарь занятий (OneFit) (G9)

Контекст: владелец ходит в зал через приложение OneFit. У OneFit нет публичного API, но каждая запись на занятие
попадает в его календарь (Google / Apple). Значит источник — **календарь**, не OneFit.

Папка: `src/features/calendar/`. Таблицы: `calendarEvents`, `calendarFeeds` (Dexie v2, уже добавлены в `src/db`).
Экспорт `calendarRoutes` сохранить. Дополнительно экспортировать из `src/features/calendar/UpcomingCard.tsx`
компонент `UpcomingCard` (ближайшие 3 события на 7 дней) — архитектор встроит его в дашборд «Сегодня».

### E1. Парсер iCalendar — `ics.ts`
- `parseIcs(text: string, source: string): CalendarEvent[]`: VEVENT → `CalendarEvent`. Поддержать: line unfolding (CRLF + пробел),
  `DTSTART`/`DTEND` в формах UTC (`Z`), с `TZID=` (использовать `Intl`/`date-fns`-free подход: трактовать как локальное время
  если TZID совпадает с локальной зоной или отсутствует; иначе грубое смещение не требуется — зафиксировать ограничение в комментарии),
  `VALUE=DATE` (allDay), `DURATION` без `DTEND`, экранирование `\,` `\n` `\;`, `SUMMARY`, `LOCATION`, `DESCRIPTION`, `UID`, `RECURRENCE-ID`.
  `RRULE` — развернуть только простые `FREQ=WEEKLY` (с `BYDAY`, `COUNT`/`UNTIL`) на 8 недель вперёд; остальное — только первое вхождение.
- `classifyEvent(title, location, description): CalendarEvent['kind']` по ключевым словам (ru/en): gym/зал/fitness/тренаж → `gym`;
  swim/бассейн/pool/aqua → `swim`; yoga/pilates/stretch/растяж/crossfit/hiit/box/group/занятие → `class`; run/бег → `run`; bike/вело/cycling/spinning → `bike`.
- Приёмка: тесты с реальными фрагментами ICS (Google Calendar export формат, событие OneFit вида `SUMMARY:OneFit: Fitness24 — Gym`), включая unfolding, allDay, weekly RRULE.

### E2. Импорт файла и подписка
- `/calendar`: кнопка «Импортировать .ics» (file input, `accept=".ics,text/calendar"`) → парсинг → upsert в `calendarEvents` по `id`
  (повторный импорт того же файла не создаёт дублей). Показать итог «Импортировано N событий, из них ближайших M».
- Подписка по URL (`calendarFeeds`): поле «Секретный адрес календаря в формате iCal» + «Синхронизировать». `fetch(url)` с обработкой
  ошибки CORS/сети: понятное сообщение «Календарь не отдаёт данные браузеру напрямую (CORS). Скачайте .ics и импортируйте файлом» —
  Google Calendar так себя ведёт, это ожидаемо; документировать это в подсказке на странице. При успехе — upsert и `lastSyncAt`.
- Инструкция на странице (сворачиваемая): как получить .ics из Google Calendar (Настройки → календарь → «Секретный адрес в формате iCal» / «Экспорт»)
  и из Apple Calendar (Файл → Экспорт).
- Приёмка: тест — импорт одного и того же текста дважды → количество событий не меняется.

### E3. Просмотр
- `/calendar`: список «Ближайшие» (от сейчас, 14 дней) и «Прошедшие» (7 дней), группировка по дню, время, место, kind-иконка;
  у событий `gym` кнопка «Начать тренировку» → `/workouts` ; у `swim`/`run`/`bike`/`class` — «Записать активность» → `/cardio/new?type=swim|run|bike|other`.
- Удаление всех событий источника (кнопка у источника). Фильтр по kind чипами.
- `UpcomingCard`: 3 ближайших события на 7 дней с относительным временем («сегодня 18:30», «завтра 07:00», «пт 19:00»), ссылка на `/calendar`; пустое состояние — «Импортируйте календарь» со ссылкой.
- Приёмка: тест рендера `UpcomingCard` с 2 событиями и с пустой БД.

Вне скоупа E (итерация 2): OAuth Google Calendar API, автообновление подписки в фоне, запись тренировок обратно в календарь.
